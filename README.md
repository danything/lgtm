# lgtm

LGTM画像を生成して共有します。<https://l.doany.io>

xool から分離したもので、ポスト通信簿は <https://github.com/danything/xool> にあります。

## 何をするか

画像をアップロードすると LGTM を重ねて webp で保存します。長辺 960px に収め、
アニメーション(GIF・WebP)はそのまま残ります。EXIF の向きも反映します。

iPhone の写真 (HEIF/HEIC) も上げられます。Safari 以外のブラウザは HEIC を読めないので、
libheif (libde265 つき) を wasm にした別の部品で読みます。HEIC を選んだときだけ取りに行くので、
ほかの画像の速さは変わりません。写真の位置情報などのメタデータは残しません。変換は画素から
WebP を作り直すのでもともと載らず、サーバーも念のため届いた WebP から EXIF と XMP を外します。

変換はブラウザの中でやります。Web Worker を 2 つ並べたパイプラインで、片方が画像を
読み込んで(GIF は giflib、アニメーション WebP は libwebp、それ以外はブラウザ自身)
Canvas で縮小と LGTM の合成をし、できたフレームから順にもう片方へ渡して libwebp で
WebP にします。読み込みとエンコードが同時に進むので、長いアニメーションでも速く
終わります。giflib と libwebp は `wasm/lgtm.cpp` のバインディングと一緒に SIMD 有効で
wasm にしたもので、イメージのビルド (`Dockerfile` の `wasm` ステージ) で作ります。
サーバーは届いた
ファイルが WebP であること・長辺 960px 以内・30MB 以内であることだけを確かめて
そのまま保存します。LGTM が載っているかまでは確かめられないので、素の画像を上げる
アカウントは削除で対処します。

追加する方法はふたつあり、ヘッダーの「画像を追加」から選ぶか、**ページのどこにでも
画像をドラッグ&ドロップ**します。Tenor 等のサイトから直接放り込めるのはこちらです。
ファイルを掴んだ瞬間に画面全体が受け取り先だと分かるようになっています。
生成が終わると、貼り付け用の `<img>` タグ(`width="100%"`)がそのままクリップボードに入ります。

一覧はタイルをクリックすると `<img>` タグをコピー、右上のボタンで拡大表示します。
自分が上げたものだけ削除でき、取り消せないので一度目のクリックでは確定待ちになります。
最初に12件だけ表示し、あとは画面が埋まるまで、スクロールに合わせて30件ずつ読み込みます。

`/` が新着、`/mine` が自分の分です。

## フォルダ

`/mine` では、自分の画像をフォルダで分けられます。作る・名前を変える・消すは一覧の上の帯から、
画像を移すのはタイルの右上のフォルダの印からです。フォルダを開いたまま追加した画像は、
そのフォルダに入ります。

フォルダは入れ子にせず、1 枚の画像は 1 つのフォルダに入ります。数が多くないので 1 段で
絞り込めれば足り、入れ子は木の画面・中身ごとの移動や削除の決まり・循環の確かめが要るわりに
得るものが少ないためです。あとで要るなら `folder` に親の列を足せば、今の形を壊さずに広げられます。

フォルダを消しても中の画像は消えず、未分類に戻ります。画像はプルリクエストに貼られているので、
フォルダの整理で消えてはいけないためです。フォルダは本人にしか見えず、新着の一覧には出ません。

## トップのグループ

トップは画像の中身でグループ (人・食べ物・アニメ・イラスト・画面・文字・猫・犬・動物・その他)
に分け、グループごとに横に流れる段で見せます。上の帯から 1 つのグループだけ、または新着順の
全部 (すべて) を開けます。中身のある段だけが出ます。

段は画面の端まで横に流れます。最初に 20 枚 (縦長の写真で 2,400px ほど) を出し、右の端に近づくと
30 枚ずつ読み足して、80 枚で止めます。終わりのタイルからそのグループのページへ行けます。
「人」の段には見出しのすぐ下に場面 (下の段落) のカプセルを並べ、トップから場面へ直接行けます。

分けるのはサーバーです。CLIP ViT-B/32 の画像の側 (MIT・8 bit で 89MB) を onnxruntime の
ネイティブ版で動かし、各グループを英語で言い表した文 (`scripts/centroids.ts`) にいちばん近い
ものを選びます。トップはみんなに同じものを見せるので、上げた人のブラウザが送った値は使いません。
新しい画像は上げたすぐあとに、それより前の画像はサーバーの起動のたびに、グループの無いものだけを
順に分けます (1 枚 80ms ほど、1 スレッド)。画像の読み込みからモデルまでは Bun の Worker
(`src/lib/server/groups/clip.worker.ts`) の中で動かし、モデルは Worker の中で 1 度だけ読みます。
onnxruntime-node は Bun では推論のあいだ呼んだスレッドを止めるので (1 枚 70ms ほど)、メインの
スレッドで動かしていたときはページのリクエストがそのぶん待たされていました。Worker が落ちたら
次の 1 枚で作り直し、サーバーを止めるときは Worker も止めます。

「人」は数が多いので (全体の 7 割)、開くと場面 (顔のアップ・ふたり・みんな・全身・衣装・ライブ・ステージ・
飲み物・食べ物と・ポーズ・そのほか) ごとの段になります。場面も同じ埋め込みから選ぶので、モデルは
もう一度動かしません。外・スポーツ・仕事はそれぞれ少なすぎたので、そのほかにまとめています。
同じ人ごとには分けません (顔の識別になるため)。

同じ写真を何度も上げたものは、トップと各グループでは一番新しい 1 枚だけを見せます。埋め込みが
0.97 以上近く、縦横比が同じものを同じ写真とみなします (1,668 枚では 18 組。0.97 より下は、ポーズや
服が違うものが混ざりました)。画像は消さないので、自分の画像 (`/mine`) と貼られた URL はそのままです。

LGTM の文字は、置いた場所が分かっているので、塗りつぶしてまわりの色で埋めてから見ます。
文字のまま見せると、ほとんどの写真が「画面・文字」になりました。アニメーションは 3 コマを
平均します。画像ごとの埋め込みを DB に残すので、グループの文を変えたら
`scripts/centroids.ts` を流し直すだけで、次の起動で全部が分け直されます。

モデルはリポジトリに入れず、イメージのビルドで Hugging Face から版とハッシュを決めて取ります。
手元では `./scripts/build-wasm.sh` が `model/` に置きます。無いときはグループ分けだけが止まります。
onnxruntime の Linux 版は使い方を Microsoft に送るので、`ORT_DISABLE_TELEMETRY=1` で止めています。

## ログイン

GitHub のみです。𝕏 でのログインは xool から分離したときに廃止しました。
それ以前に 𝕏 だけで上げた画像はそのまま残っていて、管理画面では「ログインなし」と
表示されます。

## 管理画面

`/admin` で画像数・アップロード者・日別の推移と、ユーザーの権限が見られます。
開けるのは `ADMIN_GH_LOGINS` に載っている人と、そこから権限を渡された人だけで、
それ以外には 403 ではなく 404 を返します。`ADMIN_GH_LOGINS` の管理者は画面からは
剥がせないので、渡した相手が間違いだったときの戻り道になります。

## 開発環境

リバースプロキシ (genkan) を先に立ち上げておく  
<https://github.com/danything/genkan>  
下記コマンドで立ち上げ

```sh
./s.sh i
```

`./s.sh i` は最初にブラウザ用の wasm (`src/lib/lgtm/vendor/lgtm-wasm.{js,wasm}`) と
サーバーのグループ分けの部品 (`model/`) も作ります。生成物なのでコミットしていません。`wasm/` か `Dockerfile` の `wasm` ステージを
変えたら作り直します。中身はイメージと同じステージをビルドして取り出すだけで、変わって
いなければキャッシュで一瞬です。

```sh
./scripts/build-wasm.sh        # docker
./scripts/build-wasm.sh wslc   # docker の代わりに wslc
```

CI (Docker Build Check) はイメージをビルドしたあと起動し、Chromium で PNG と GIF を
実際に WebP へ変換できるか確かめます (`tests/wasm.spec.ts`)。emsdk の更新は自動で
マージされるので、ビルドが通るだけでなく wasm が動くことまでここで見ます。手元では
ビルドしたイメージを起動して、それに対して流せます (`BASE_URL` で向き先を変えられます)。

```sh
bunx playwright test  # http://localhost:3000
```

### 各自の設定

`compose.yml` は全員共通で、直接編集しません。手元だけの設定は
`compose.override.yml` に書きます。Docker Compose が自動で読み込んで
`compose.yml` に重ねるため、起動コマンドは変わりません。このファイルは
gitignore してあります。

```yaml
# compose.override.yml
services:
  lgtm:
    environment:
      # GitHub OAuth アプリ。コールバックは https://l.localhost/api/gh/cb
      - GITHUB_CLIENT_ID=xxxxx
      - GITHUB_CLIENT_SECRET=xxxxx
      # OAuth の state に使う任意の文字列
      - HASH=xxxxx
      # /admin を開ける人。空なら誰も開けません
      - ADMIN_GH_LOGINS=xxxxx
```

重ねた結果は下記で確認できます。

```sh
docker compose config
```
