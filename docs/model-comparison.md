# トップのグループ分け: ライブラリとモデルの比べ直し (2026-11-28)

#256 ではモデル 2 つ・動かし方 4 つだけを比べ、GitHub のスター数や保守の様子を見ずに
onnxruntime-node + CLIP ViT-B/32 (Xenova の 8 bit) を選びました。ここでは推論のライブラリを
9 つ、モデルを 18 (それぞれ 32 bit と 8 bit) 比べ直します。

## 結論

**入れ替えません。** 今の CLIP ViT-B/32 より、調整に使っていない 208 枚で有意に当たるモデルは
ありませんでした (同じ画像で対にした検定で、速さと大きさが今と同じくらいのもののうち、いちばん良くて p=0.34)。重複の見分けは、
どのモデルも今より多く間違えます (後で書くとおり、今のモデルに有利な測り方ではあります)。
ライブラリも、onnxruntime-node より速く、ほかが悪くならないものはありませんでした。

ただし 1 つ、前の PR の思い違いが見つかりました。**onnxruntime-node は Bun で、推論のあいだ JS の
スレッドを止めます** (1 枚 75ms のうち 70ms)。#256 には「JS のスレッドの外で動く」と書きましたが、
そうではありませんでした。Bun の Worker に入れると、速さはほぼ同じ (86ms) のまま、止まるのは
1ms になります。#272 で、画像の読み込みからモデルまでを Worker に移しました (下の「次に考えること」の 1)。

## 測り方

- 本番の画像 1,668 枚の手元の写しを、wslc のコンテナの中だけで使いました (外には出していません)
- 前処理はアプリと同じ (`src/lib/server/groups/pixels.ts`: LGTM の印を塗りつぶし、真ん中の正方形を縮める)。
  正規化の平均と分散はモデルごとの値 (SigLIP は 0.5/0.5)
- 精度: 文の調整に使った 209 枚・使っていない 208 枚 (held-out) のグループ、人の場面 90 + 90 枚で、
  文の中心にいちばん近いものが正しい割合。文はモデルごとにその文の側で埋め込み直しました
- 重複: 今のモデルで 0.97 以上だった 18 組 (目で見てどれも同じ写真) と、0.95〜0.97 の 27 組 (目で見て別の写真)。
  モデルごとに一番良いしきい値を選んだときの誤りの組の数
- 速さ: 1 スレッド・1 枚ずつ・31 枚の 2 枚目からの中央値。ほかの測りを止めてから測り直しました
- 8 bit は onnxruntime の動的量子化 (重み uint8)。今のモデルは Xenova が配っている 8 bit のファイル
- 版: Bun 1.4.5 (distroless)・onnxruntime-node/web 1.31.1・@huggingface/transformers 4.3.2・openvino-node 2026.4.1・
  @tensorflow/tfjs-node 4.22.0・candle 0.11.1 (Rust 1.100.0)・Python 側は onnxruntime 1.32.0・open_clip 4.2.2・transformers 5.24.1
- スクリプトは [`model-comparison/`](model-comparison/) (画像・名前・正解の一覧はリポジトリに入れていません)

**今のモデルに有利な点**: グループの文 (`scripts/centroids.ts`) は今のモデルで調整したもので、ほかのモデルに
合わせ直してはいません。重複の 45 組も、今のモデルの値で選んだ組です。そのため「調整 209 枚」と「重複」は
今のモデルが勝ちやすく、比べるときは held-out の 208 枚を主に見ました。

  見る必要があるが、入れ替えるなら 0.97 のしきい値と `dupKey` の作り直しに加えて、組を選び直して目で見る手間が要る

## 入れ替えない理由

決め方は「今より明らかに良く、ほかが悪くならないものがあれば入れ替える」でした。

- 精度: 今と同じくらいの速さと大きさで有意に良いモデルが無い (p がいちばん小さいのは OpenAI B/32 の別の 8 bit で 0.34、TinyCLIP 40M で 0.36)。有意に出た 32 bit の LAION B/16 は 6 倍遅い
- 重複: どれも今より誤りが多い
- 入れ替えの手間: 文の側の埋め込みの作り直し・DB の 1,668 枚の埋め込みの作り直し・重複のしきい値の選び直しと目での確かめ。
  多くは画像の側だけの ONNX が配られておらず、自分で書き出して置く場所も要る
